成果物の出力方針 ―「HTMLしか読まない」

全プロジェクト共通ルール ／ 認知負荷対策

従来: 文章ログを読む
  • 1アカウント 4〜8窓のテキストを追う
  • 窓が増えるほど読む量が爆発
  • 「ここ何やってたっけ?」の復帰コスト大
  • サブスク切替時のスイッチングコスト
人間がボトルネックになる前回の限定開放で痛感した反省点
今回: 成果物を HTML 化
  • 報告は全部 HTML + SVG + 画像で受ける
  • 直感的に「見て」判断できる
  • HTMLプレビュー = 作業の引き継ぎ資料
  • 待ち時間に別ラインをどんどん進められる
並列数を上げても捌ける公式も HTML プレビュー活用を推奨

補足: 1アカウント運用で文章を読む余裕があるなら Markdown でもOK。多窓・多アカウントで効いてくる対策。

導入状況

  • ~/.claude/CLAUDE.md … 全プロジェクト共通の方針として設定済み（このセッション環境）
  • scraping/CLAUDE.md … 本リポジトリの規約として追加・コミット・プッシュ済み

ローカルへ恒久反映するための貼り付け用テキスト

お手元マシンの ~/.claude/CLAUDE.md に貼れば、どのプロジェクトでも常時有効になります。

＃ 成果物の出力方針（全プロジェクト共通）

＃＃ 原則:「HTMLしか読まない」
作業の報告・成果物は、原則として自己完結型の HTML ファイルとして出力する。
CSS / JS / 画像は inline または data URI で埋め込み、図解は SVG で描く。
外部ファイルへの依存をなくし、プレビューで「見て」判断できる形にする。
長文のテキストログを追わせない。

＃＃ なぜこうするか
- 従来: 文章ログを読む運用だと、窓やアカウントが増えるほど読む量が
  爆発し、人間がボトルネックになる。
- 今回: 成果物を HTML 化すると、直感的に「見て」判断でき、HTML
  プレビューがそのまま引き継ぎ資料になる。並列数を上げても捌ける。

＃＃ 具体的なやり方
- 調査 / レポート / 比較 / ダッシュボードは、単一の自己完結 HTML で出力する。
- 図解は SVG、スクリーンショットや生成画像は img（data URI 埋め込み）で表示。
- Claude Code on the web では Artifact として公開し、プレビューで見られるようにする。
- 成果物は各プロジェクトの output/ や reports/ 等にも保存し、引き継げるようにする。

＃＃ 例外・補足
- 1 アカウント運用など、テキストを読む余裕がある単純作業なら Markdown でもよい。
- 多窓・多アカウント・並列作業では、HTML 出力を徹底する。

※ 上のブロックの全角「＃」は、貼り付け後に半角「#」へ置き換えてください（Markdown 見出しの体裁維持のための表示用エスケープです）。コピーボタンは自動で半角に変換します。
