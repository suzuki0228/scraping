# 「儲かっている会社」調査フレームワーク（Web系版）

> 前提: ここでの「儲かっている」= **営業利益**。本業でいくら稼げているか。
> 株式売却益（ARR・売上総利益・コンプス）での儲け方もあるが、初心者がスモールビジネスから
> 確実に金を得る最短経路は「営業利益から受け取る」ことである。営業利益さえあれば売却先も見つかる。

このドキュメントは、貼り付け元のメソッドを **手を動かせるテンプレート / チェックリスト** に落としたもの。
事業領域を `Web系` に固定して具体化してある。別領域に流用する場合は §0 の領域定義だけ差し替える。

---

## 0. 領域の定義（最初に1行で言い切る）

調査は「対象領域」を1行で言い切れるまで始めない。曖昧だと比較対象がぶれる。

- 悪い例: 「Web系で起業したい」（広すぎ）
- 良い例: 「**中小企業向けの予約管理 SaaS を月額課金で売る**」「**EC事業者向けの広告運用代行**」「**特定業界向けバーティカル SaaS**」

記入欄:

| 項目 | 記入 |
|---|---|
| 対象領域（1行） | （例: 〇〇業界向け予約 SaaS） |
| 提供形態 | SaaS / 受託 / 広告 / EC / メディア / マッチング 等 |
| 顧客 | 誰が（業種・規模） |
| 課金 | 月額 / 従量 / 成果報酬 / 一括 |
| 自分の目標営業利益（年） | 例: 3,000万円 |

### 領域の足切り基準（重要）

- **最低基準**: 自分の目標営業利益の **10倍以上** を稼いでいる会社が「容易に・多数」見つかる領域であること。
  - 例: 目標が年3,000万なら、営業利益3億円超の類似企業が複数すぐ出てくるか？
- **危険シグナル**: 類似ビジネスで儲かっている会社が見つからない / 参入企業数に対して儲かっている割合が極端に低い領域（D2C が代表例）。
  - 「自分は他人と違うから勝てる」は捨てる。他人ができないことは自分にもできない。理由を深掘りする必要はない。

→ **儲かっている会社が見つけられない領域は、その時点でダメ。** 次の領域へ。

## 1. 情報チャネル別チェックリスト

5つのチャネルを総当たりして、対象領域で儲かっている会社を「調べ尽くす」。
Web系で特に効くチャネルに ★ を付けてある。

### チャネル1 ★ IR（上場企業の投資家向け開示）— 最重要

上場企業は財務詳細〜今後方針まで開示義務がある。**宝の山。** 領域内の上場企業のIRは全部見る。

- [ ] 領域内の上場企業をリストアップ（§3のソース参照）
- [ ] 各社の **決算説明資料 / 有価証券報告書** を入手
- [ ] **売上規模・利益率・利益額** を記録
- [ ] **コスト構造**（何にいくらコストがかかるか → コピーに何が必要か分かる）
- [ ] **変動要因**（売上が伸びた理由＝成功のヒント / 販管費が上がった理由＝競争過熱のシグナル）
- [ ] **今後の方針**（その会社が「これをやれば儲かる」と思っている方針＝大ヒント）
- [ ] セグメント別の売上・営業利益だけでなく「**何が・いくらで・誰に・なぜ売れているか**」を言語化
- [ ] 新規上場（IPO）企業は領域外でも目を通す習慣（トレンド把握）

> IRに財務数値しか無く競争力が読めない時 → チャネル4（営業資料・LP）で「なぜ自社を選ぶべきか」を読む。

Web系での具体ソース: EDINET（有報）、TDnet（適時開示）、各社IRページの決算説明資料PDF。

### チャネル2　非上場企業の決算（官報）

非上場は外から把握しにくいが、**官報の決算公告**から取れる場合がある。情報は断片的。

- [ ] 官報決算データベースで領域内の非上場企業を検索
- [ ] 主に見るのは **純利益・利益剰余金**（他項目は単体だと意味を持ちにくい）
- [ ] 儲かっていない会社は「**なぜダメだったか**」を把握して同じ失敗を避ける

### チャネル3　投資情報

投資がなされている＝そこに何らかの根拠（数値）が存在する。

- [ ] 領域内の資金調達・M&A・出資のニュースを収集
- [ ] 公開される数値（導入社数など）は部分的。「根拠数値が存在する」と理解しておく
- [ ] ⚠️ ベンチャー投資は注意: 調達できても成功率は高くない。儲かる保証ではない

### チャネル4 ★ 企業によるリリース（営業資料・LP・マーケサイト）— Web系で必須

企業は営業・マーケ・採用のために状況を部分開示する。**単価 × 導入社数 ≒ 売上推定**ができる。

- [ ] **営業資料をダウンロード**（単価・プラン・機能を把握）
- [ ] **LP / マーケサイト**から導入社数・導入企業ロゴを把握
- [ ] **デモ利用・トライアル**を実際に触る
- [ ] 「なぜ他社でなく自社か」の訴求文を全部読む（＝競争力の核）
- [ ] ⚠️ マーケ情報は誇張前提で割り引く（「導入社数（デモ含む）」のトリックに注意）
- [ ] 知人経由でも実態情報を集める（投資家向け・採用広報の数字は実態と乖離）

> 調査段階から「この商品を買う理由はこうだろう。でも自分の提案の方が良い。なぜなら…」と
> **反論（パンチ）を組み立てながら**読む。

### チャネル5　業界紙 / 専門メディア

一般経済メディアは検討の契機止まり。業界紙は読者を業界内に限定するため詳細情報が取れる。

- [ ] 対象領域の業界紙・専門メディアを特定（SNS / 専門誌サイト / 知人ヒアリング）
- [ ] 定期購読 or バックナンバーで業界内トレンドを把握

Web系での具体例: TechCrunch Japan系・THE BRIDGE・各VCの調査レポート（SaaS Annual Report 等）・ITmedia・MarkeZine・Web担当者Forum など。

## 2. エクセレントカンパニーの抽出と「ミニ版」設計

儲かっている会社を数社見つけたら、ここからが本番。

### 2-1. 抽出（同領域で「儲かる/儲からない」の差分を取る）

同じ領域でも儲かる会社と儲からない会社がある。そこには **必ず成功要因** がある。
成功要因こそが、その領域であなたに競争力を与えるもの。

- [ ] 領域内で営業利益が突出している会社を 3〜5社に絞る
- [ ] 儲かっている会社 vs 儲かっていない会社で **何が違うか** を差分化
- [ ] その差分（＝成功要因/核となる戦略）を1〜2行で言語化

> 例（アイリスオーヤマ）: 表面的には他社と同じ品揃えなのに突出して儲かる
> → 調べると **問屋と統合した垂直統合モデル**（情報・コスト・スピードの優位）が核。
> → 「敢えて捨てられている小さな市場で、可能な限り垂直統合した"ミニ・アイリスオーヤマ"を作り、
>   弱小メーカーを撃破する」という戦略が立つ。

### 2-2. 徹底調査（1社あたり数時間）

絞り込んだ各社について、以下を全部見る（巨大企業を除けば1社数時間で終わる）。

- [ ] 沿革
- [ ] 経営者インタビュー
- [ ] 商材の活用事例（導入事例）
- [ ] 営業資料
- [ ] （Web系追加）採用ページ／技術ブログ（組織・技術スタック・内製範囲が読める）

### 2-3. 「ミニ版」設計

- [ ] エクセレントカンパニーの **成功要因（核戦略）をコピー**
- [ ] その会社が **敢えて捨てている小さな市場** を特定
- [ ] そこで核戦略を効かせた **ミニ版** を設計し、弱小プレイヤーを撃破する筋を描く

## 4. 1領域あたりの調査ワークシート（テンプレ）

調査した企業ごとに以下を埋める。`src/` のスクレイパーで一次データを集め、ここに転記する。

```
## 企業名:
- 証券コード / 上場区分:
- 対象領域との関係:
- 売上高:
- 営業利益 / 営業利益率:
- コスト構造（主要費目）:
- 売上変動要因:
- 今後の方針:
- 何が・いくらで・誰に・なぜ売れているか:
- 成功要因（核戦略）の仮説:
- 自分の「反論（パンチ）」:
- 敢えて捨てている小さな市場:
```

---

## 5. 進め方（このリポジトリでの運用）

1. §0 で領域を1行に固定する
2. `src/` のスクレイパーでチャネル1（IR/EDINET）の一次データを収集 → `reports/` に出力
3. §4 のワークシートを企業ごとに埋める
4. §2 でエクセレントカンパニーを抽出し、ミニ版を設計する
5. 足切り基準（§0）に引っかかったら、潔く次の領域へ
